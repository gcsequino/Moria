# One-million-object header-window trial v8

This is an exploratory single-host implementation trial, not production scale or SLO certification. The frozen source is `20261031T090947263284Z-data-header-qualification-v6`; the exact release executables, source manifest, driver and commands are identified in `manifest.json`. The Moria native proof resource lock was exclusive for the million run. Its container admitted four CPUs, 12 GiB memory and 24 GiB combined memory/swap; other host activity was not globally fenced.

The independent oracle passed for all 1,000,000 generated 4,096-byte rows, including exact count, source sum and XOR. The source has 249 immutable files and 4,019,642,204 physical data bytes. The typed projection occupied 11,666,522,112 bytes. Source generation took 22.75 seconds, publication 387.84 seconds, native indexing/projection 1,094.87 seconds and the oracle 69.43 seconds. The recorded total was 1,746.65 seconds (29 minutes 6.6 seconds).

Protected HTTP used the unchanged seeded workload, 30-second open-loop windows, original ten-second arrival deadlines and the complete query population. It offered 20, 50 and 100 requests/second. Results were 600/600 successful, 995/1,500 successful with 505 RESOURCE_LIMIT/429 responses, and 1,001/3,000 successful with 1,999 RESOURCE_LIMIT/429 responses. Reported p95 values of 317.97, 2,681.46 and 2,311.50 milliseconds use **all arrivals**, including errors; they are not successful-only latency percentiles. The higher offered rates failed. Per-arrival records and class outcomes are retained in the population directory. No query was narrowed to improve the measurement.

There are 118 resource samples. Cgroup memory peak was 12,885,725,184 bytes; maximum sampled current memory was 12,884,893,696 bytes. These include shared file cache and kernel memory. Maximum individual process RSS was 242,102,272 bytes; summing RSS would double-count shared pages. The final cgroup recorded 90,607 memory-max events and zero OOM/OOM-kill events. These data do not establish a production resource requirement.

A separate bounded read-only PostgreSQL observer captured 95 valid one-second HTTP activity/wait samples. It observed actual protected query SQL and both shared/exclusive advisory waits on the environment admission key; this supports further protected-query and action-publication investigation, not a causal attribution by itself. Observer query mean/max were about 1.10/4.79 milliseconds. `pg_stat_statements` was not installed. The first observer attempt failed TypeScript transformation; the second captured its samples but exited nonzero when the fixture shut PostgreSQL down without a client error handler. Both failures are preserved, and neither altered the trial settings or its exit-zero result.

The 1,000-row exact/HTTP preflight also passed. No binary, authority check, accepted deadline, query scope or resource limit changed during either measured run. Subsequent protected-plan/action changes require a separately frozen same-offered-load comparison.
