# Target-specific recursive ACL plans

The shared filesystem ACL kernel now selects custom PostgreSQL query plans for
its parameter-dependent recursive closure queries. The setting belongs only to
that function. It does not cache authority across statements or change policies,
classification inheritance, source proofs, live revocation, error priority,
transaction isolation, locks, leases or deadlines.

The first real 16-head producer diagnostic on the earlier administrator-kernel
baseline reached only 15 candidates before its unchanged 120-second deadline
(120.145 seconds; 49.705 seconds in 5,004 ACL calls). A disposable-database
function-setting prototype completed all 16 in 103.517 seconds, with 32.806 seconds
in 5,228 ACL calls. All 67 configured input fixtures were retained. The prototype
used unchanged earlier native artifacts and is a planner experiment, not a
qualification of the combined production build or a capacity certification.

The actual SQL change and regenerated schema fingerprint were then built with
the integrated lease renewal and bounded staging collector. All nine native
artifacts, static checks and 109 native units pass. The full filesystem Source
security file passes 21/21 with no skips or cancellations, including current
revocation, inherited restrictions, error ordering and the 512-capability
administrator conjunction cases. Controller, all three scratch pools and
private temporary files were removed after the run.

The full original Pipeline/Connector file and ten-case service evaluation are
running on this production build at this checkpoint. Their results remain
required; the isolated producer result does not satisfy those gates. No live
installation migration or production workload qualification is claimed here.
