# Incomplete million-row trial and measured projection plan failure

This actual one-million-row, 4 KiB release trial is incomplete. It passed mandatory source/artifact preflight, allocated permanent native UIDs, produced real bounded Parquet, published the native V2 Dataset, and sealed all 16 native reducers. Source publication took 644.97 seconds. The full source/effective oracle and protected HTTP workload did not execute; no capacity or SLO pass is claimed.

Snapshot: `/tmp/moria-proof-snapshots/20261030T225648560535Z-factored-million-release-v3`; manifest SHA-256: `fd2364737f624ec0c09342f3bc13f221070e1ec057a0ad6d92a60a591ec246a2`. Exact Cargo-derived copied executable hashes, embedded metadata preflight, source manifest, generated schema, raw phase logs, and per-process/cgroup/disk samples are retained. The derived runner and read-only diagnostic source hashes are recorded. The workload used four CPUs and a 12 GiB container cap while other local proofs also ran; these are exploratory timings.

The projection candidate query walked the remaining population for every page. At 25,000 completed rows, actual custom and generic plans each scanned 975,000 stage rows, executed 975,000 overlay index probes, and top-N sorted before returning 1,000 rows. They took 14,042.517 and 14,220.616 ms with about 10.1 million buffer hits. LLVM JIT was unavailable.

A read-only alternative on the same live database selected ordered keys independently from source and creation populations, materialized their bounded union, then fetched payload and overlays by UID. At 43,000 completed rows, custom and generic plans returned 1,000 rows in 17.355 and 13.774 ms with about 16,000 buffer hits. Both complete sanitized physical plans are retained. The query did not mutate production SQL or the binary under test. This diagnoses a page-planning failure; it is not an end-to-end performance result.

The slow trial was paused rather than allowed to perform a population walk for every page. Container `moria-data-factored-million-v3` retains the original PostgreSQL cluster and synthetic source/native objects in its writable layer. Copy data before unpausing: expired worker leases may cause the fixture to fail and clean up. Corrected source requires a fresh regression and actual pipeline run, followed by protected open-loop reads and Actions before advancing population.
