# Qualified million-object trial, v6 driver

The exact one-million-object source/effective/UID oracle passed. The protected HTTP workload failed its latency/throughput targets; this trial is exploratory and is not production capacity certification.

Runtime source was frozen at `20261031T051559526844Z-qualified-million-release-v5`, manifest SHA-256 `2857b66c773549392550443cc1159b9fef3f92e4e913283b9528bae86047d004`. The separately frozen corrected v6 driver and exact compiler JSON artifact paths/digests are recorded in `manifest.json`. Neither runtime source nor binary was swapped during execution. Earlier driver permission, SQL parameter, optional-budget and duplicate-action failures remain in their original evidence directories.

The source contains 1,000,000 rows of 4096 logical bytes, 4,019,642,204 physical data bytes across 249 objects. Exact sum/xor hashes are in `population-1000000/result.json`; the typed projection occupies 11,666,620,416 bytes. Identity took 77.28s, source production 24.45s, source publication 686.96s, indexing/projection 2394.69s and exact oracle 72.51s. Whole trial 3353.72s. Qualified snapshot verification was disproportionately slow and triggered separate counted reader investigation.

The HTTP mix offered 20, 50, 100 arrivals/second for 30 seconds each: 35%detail,30% page,15% filter+sort,10% single action,5% five-distinct-object multi-action,5% exact-one-UID aggregate; 80% uniform/20% hot 1% UID distribution. Page/filter-sort retain whole-population UID/rank scope; optional query budget is omitted because that API requires an explicit restricted UID scope. Page projection is seven fields and excludes payload. The source uses one workload, two markings and full visibility. Raw scheduled-arrival records include admission failures and timeouts in their denominator.

At 20/s 600/600 requests completed with p95 latency 1238ms. At 50/s 798/1500 completed, with 702 HTTP 429; at 100/s 850/3000 completed, with 2150 HTTP 429. The high-load median includes quick rejection responses and does not imply acceptable useful-work latency. Exact per-class counts, latency distributions, offered and achieved rates are in `population-1000000/http-baseline.json`; raw records are retained for all 600/1500/3000 arrivals. Small 1k smoke completed 40/40 across all six classes.

Container limits were 4 CPUs, 12GiB memory and 24GiB memory+swap, on a shared host. `resources-1000000.jsonl`, `resource-summary.json` and the read-only diagnostic preserve actual observed resource/phase state. The captured verifier had roughly 4.07 million PostgreSQL transactions and 1.68 million read syscalls; the diagnostic does not establish individual function causality because function tracking was disabled in that trial. Native verifier tiny-range I/O and whole-population typed UID query plans are subsequent measured investigations.

The result JSON's default remaining-work list predates the external HTTP callback; `http-baseline.json` is authoritative for the HTTP experiment. Two retained generations, overlays/history, wider-than-memory distributions, repetitions, sustained peak/soak, recovery and failure-domain capacity tests remain required. No ten-million trial or full-profile pass is claimed.
