# Dataset I/O execution validation

Dataset I/O used to validate a private credential's execution inside its current session lookup and then repeat the same execution check immediately afterward. The successful private session path now attaches the actual execution UUID it validated to its local result. Dataset I/O shares that result only when it names the exact requested execution. Each SQL call still obtains fresh session and execution authority; no stored credential, caller flag or cross-call authority cache can skip validation. Ordinary credentials, different executions, task/owner/fence/namespace checks and final publication validation retain their existing paths.

The real PostgreSQL regression counts two execution checks on the original artifact and exactly one on the new artifact. It compares the resulting namespace authority for ordinary and accepted private credentials, verifies the marker is absent from ordinary state, denies a mismatched private task, and leaves prepared output invisible. The full Catalog file passed21/21 and private-job authority12/12, with zero skipped/cancelled. Static quality, all nine exact native artifacts and106 native units passed.

The first regression fixture used the wrong namespace revision and is retained separately. A later initial full Catalog run hit a MinIO Arrow-output prepared-event timeout; its other cases passed. The unchanged full-file repeat passed with the original300-second root and event limits. That timing failure is retained rather than converted into a capacity or reliability claim.
