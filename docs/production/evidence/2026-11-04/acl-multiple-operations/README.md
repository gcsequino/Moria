# Current filesystem geometry shared across operations

A Dataset output asks for both read and write authority on every bounded I/O guard. Previously, one batch traversed the same live filesystem/source graph separately for each operation. The batch now computes bounded operation outcomes together and raises the selected outcome in the original request order. Every target operation still needs its own allow and lacks any applicable deny; provenance/dependency targets still require read. Current and pinned Source file proofs and exact inherited labels remain part of the graph.

The two internal operation helpers and read-only batch use a single calling-statement snapshot (STABLE). Only the existing invocation-local batch map holds outcomes; subsequent statements reconstruct authority. Neither row/advisory lock behavior nor durability settings changed. Bounded I/O checks before/after physical work and final publication remain separate fresh guards. Internal helpers revoke PUBLIC execution, and denied batches return no labels or partial results. Unexpected SQL errors propagate normally.

The full filesystem Source integration file passed **20/20**, zero skipped/cancelled, in **27.908 seconds**. The added regression covers cyclic/duplicate graph edges, exact protected labels and Source proofs, independent read/write denial, a live declaration-file deny, all six mixed-entry orders of SOURCE_FILE_PROOF_REQUIRED, NOT_FOUND, and FORBIDDEN, and rejection of forged internal calls by a restricted role. A deterministic, test-only post-geometry barrier commits a concurrent write deny: the in-flight statement retains its authority snapshot and the next fresh statement and scalar check both reject. No test barrier or hook is installed in production.

Actual PostgreSQL function counters demonstrate the regression: the original implementation traversed one origin **3 times**, failing the expected count of 1; the changed implementation traverses it **once** for read/write/publish. The retained red fixture predates the added concurrency block; its counter assertion and all preceding setup are unchanged. An earlier green attempt was intentionally stopped after the new regression passed because integration slot assignments overlapped; it is retained as an interrupted run, not a successful full gate.

The exact frozen production source built all nine native executables in **18.409 seconds**; full static checks plus all-nine provenance verification and **81 native unit tests** passed in **23.902 seconds**, zero ignored. source-provenance.json records the source archive, combined schema, and native source digest; artifacts.json records each executable hash. The SQL red/green front-gate overlays intentionally did not invoke their unchanged native binaries and are not native artifact qualification.

A full Pipeline acceptance run and a fresh native-catalog post-I/O publication guard run on this cohort are still required. Functional/security correctness and reduced traversal count do not certify production throughput or capacity.
