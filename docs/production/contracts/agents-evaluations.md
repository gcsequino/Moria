# Native agents and evaluations

## Scope and existing declarations

`Agent`, `AgentAdapter` and `EvaluationSuite` already have validated resource declarations and compiler reference checks. Before this implementation they had no execution host, LangGraph adapter, evaluation runner or public lifecycle endpoints. The first adapter remains LangGraph.js inside a digest-pinned OCI guest; Rust owns authentication, durable scheduling, supervision, model/tool admission and publication. LangGraph state is private adapter state, never the platform execution model. Checkpoint/resume is unsupported until a separately tested capability is enabled.

## Agent admission and identity

The native domain API accepts `POST /api/v1/agents/{resource UUID}/executions` with `Idempotency-Key` and `{input,wait?}`. It exposes `GET /api/v1/agent-executions/{UUID}`, `/events?after={sequence}` and `POST .../cancel`. The transport supplies a private verified session. Request JSON cannot choose actor, environment, application, release, adapter, model endpoint, worker, resource class or parent execution.

Admission pins the active Agent declaration, AgentAdapter declaration, both OCI artifact digests, full typed input/output descriptors, model binding/configuration, release, current actor/session, actual input-reference evidence and complete classification. A logical key is scoped to environment, resource and actor/application. Replay normalizes against the originally accepted input descriptor and cannot silently execute a newly deployed release. The declared application must match the authenticated application; this first profile does not manufacture an unconstrained delegated identity.

Exact `<Agent UUID>:invoke` and `<EvaluationSuite UUID>:run` scopes are supported alongside explicitly granted legacy `agents:invoke` and `evaluations:run`. The immutable binding retains the selected operation. Protected Source/dependency/file ACL checks follow that operation without granting filesystem browsing; independent Model invocation and Dataset read permissions remain required.

An Agent can invoke and inspect its direct Function children through the native broker. The actual accepted execution/delegation ancestry bounds depth, rejects resource cycles, and fences descendants after parent cancellation. Before a caught child outcome returns, the broker durably records the child's actual consumed classifications and dependency evidence in its parent. A failed or uncertain child observation can block parent release; guest JSON never supplies an actor or classification. The [current Agent/Function integration proof](../../benchmarks/native-observation-journal-20261030-trial-010-passed.tap) passes 17 checks with no skips, including failed-child classification and cancellation of a running child within ten seconds. Service-origin child composition requires the separately registered purpose mappings; it cannot widen a generic service capability.

Agent state is queued, running, succeeded, failed or cancelled. Default deadline is ten minutes, including queue and startup. A lost user-code attempt fails with its last protected events; another worker may clean its container or publish already sealed output but cannot restart its graph. Generic execution claim/seal cannot operate on Agent tasks. Registered native agent workers claim and seal through private owner/host/incarnation/resource-class capabilities with increasing fences. Leases use the database clock and are renewed while healthy; shared class budgets apply across all queues.

## Shared isolation, separate authority

Agents reuse the native Docker/framing/accounting mechanism and required protected broker. Their immutable bindings, source metadata, acknowledged epochs, attempt journal and successful receipts remain separate from Function invocations. No synthetic Function resource or Node platform worker participates. A private context variant validates current agent authority and its exact live owner-bound lease before every protected operation. Function checks remain in the Function variant.

The guest has a read-only root, unprivileged identity, no network, no catalog/host/provider credentials, bounded memory/CPU/PIDs/output, and the existing result-complete handshake. Native cancellation stops its container within ten seconds. Adapter capabilities `events` and `cancel` are required; declarations advertising unsupported checkpoint/resume fail before execution. A preloaded image digest is verified before user code starts. Agent artifacts and adapter dependency locks are release inputs.

## Model and tool boundary

The adapter uses the generated ontology SDK and supported platform API through supervised messages. Tool calls carry stable logical IDs. Action keys are derived from the execution and logical call ID and are durably mapped before dispatch; later graph failure cannot undo an already committed action receipt. The first profile permits ordinary protected reads and per-call readWrite actions. It does not translate an agent into a single atomic editProposal transaction.

`POST /api/v1/agent/model` is a private guest broker route, with a stable call ID and a bounded normalized model request. The native binding chooses the model; a guest cannot choose an endpoint, destination, provider secret or alternate actor. `NativeModels` applies current actor/resource/application and model-destination policy to the union of source/input/read/model classifications before inference. Success, failure and uncertain provider outcomes retain their classification and structural call mapping. Provider secrets and prompt/data bodies never enter service logs. Cancellation cannot refund model cost or retract a previously dispatched request.

Model metadata admission also checks the actual Source provider/policy declarations and any operator-approved SecretReference. Before code starts, accepted Agent classifications include declaration and approved material labels, and required operations include exact Model invocation and Secret use. The immutable Agent row and any Evaluation Agent pin retain the approval identity, generation and incarnation separately from the provider route. Current callback and retained gates compare that captured reference; a missed approval disable/reenable pulse cannot revive accepted work. Registered metadata admission uses the real approved service purpose without manufacturing a session or making a provider request.

Results, logs and traces are protected retained data. Publication revalidates actual read/reference evidence and current source/model authority, then commits typed output, its marking union and execution completion in one transaction. Retained inspection repeats current authorization and consumed-content checks; it cannot launder historical data through changed row attributes. Thirty-day expiry withholds content while preserving the logical key. Structural traces expose call kind/status/ID and reported usage without prompt or response content.

## Evaluations

Evaluation admission pins the suite, Agent release/model configuration, fixture Dataset generation/snapshot and evaluator OCI digest. Cases are bounded immutable rows with stable case IDs, normalized input hashes, expected assertions and explicit repeat numbers. A retry is a new recorded case attempt, never a rewrite of an old score. Bounded native workers schedule cases without holding a global queue lock. Agent and deterministic evaluator code run under the same isolation and current policy boundaries; evaluator code receives only its case's authorized expected/result envelope.

Public evaluation state is queued, running, completed, failed or cancelled. Completed may contain failed assertions and reports pass/fail/error separately. Every case retains result/error, duration, reported usage and protected tool/action trace references. Mutation-capable evaluations require a dedicated explicitly registered evaluation environment; production credentials cannot be supplied in request JSON or fixture data. Default overall deadline is sixty minutes. Parent cancellation fences unfinished child attempts; committed tool effects remain independently visible.

Comparison requires identical case IDs and evaluator versions. Incompatible results report noncomparability. Repeats remain separate samples with reported variance; inference is not declared deterministic. LLM judges are an explicit later capability with their own recorded model configuration and cost, never an implicit replacement for deterministic evaluator code.

## Evidence and delivery boundary

Implementation must prove real authenticated admission/replay, actual locked LangGraph guest execution, native model and ontology calls, stale-owner rejection, single-attempt worker death, cancellation, classification retention on failed callbacks, atomic result receipts, evaluation pass/fail/error and comparison. A separately recorded configured local-model run complements deterministic local provider protocol fixtures. Production capacity, deployment topology and default caller cutover remain separate N24/N28 obligations.

The [native service/Agent/Function proof](../../benchmarks/native-service-profile-20261030-trial-003-green.tap) passes 42 tests with no skips. It includes the actual locked LangGraph guest, protected model and ontology calls, usage strings, classification retention, a committed action surviving later graph failure, lease renewal, held-provider revocation, cancellation, supervisor death, real lost COMMIT acknowledgement, ordinary-session expiry and single-attempt behavior. The Agent SDK and public CLI call the persistent native HTTP API; the worker CLI replaces itself with the native process, verified through `/proc`. This evidence does not certify production capacity.

The [native evaluation proof](../../benchmarks/native-evaluations-20261030-trial-015-passed.tap) passes seven tests with zero skips. It loads an actual pinned Iceberg Dataset once, records ten distinct case/repeat rows, supervises eighteen single-attempt Agent/evaluator code jobs, checks exact pass/fail/error counts and score statistics, and calls the real native model gateway. It covers accepted authority after ordinary-origin expiry, release pinning across redeployment, evaluator platform denial, comparison compatibility, current classification, public SDK/CLI replay, parent cancellation stopping held inference and OCI work within ten seconds, and actual root receipt COMMIT acknowledgement loss followed by worker SIGKILL and one durable receipt. [Failed trials and the correction ledger](../../benchmarks/native-evaluations-20261030-trials.json) remain separate immutable evidence. These functional proofs do not certify production capacity.

The initial case Dataset profile is explicit: `caseId`, `inputJson` and `expectedJson` are UTF-8 columns. Each typed JSON envelope is bounded and normalized against the pinned Agent descriptors; nested Parquet columns are not silently treated as supported fixture schemas. The dedicated environment registration caps total expanded cases, repeats and cross-replica case concurrency. Arbitrary Agent/evaluator code remains single-attempt. PostgreSQL serialization/deadlock aborts may retry only structural admission or publication of an already sealed result within its original deadline; ambiguous transport commits never cause a code retry.

Root cancellation commits its authority fence first, immediately denying every accepted descendant through the current parent chain. Native cleanup closes descendant bookkeeping without holding parent row locks while waiting for children. Active and orphan OCI cleanup serialize per execution. Evaluation SDK and CLI operations use the persistent authenticated native HTTP API; `moria evaluations worker` replaces the CLI with the registered native worker before creating any Node workspace.

Function, Agent, Evaluation and Pipeline cancellation return exactly `{id,cancelRequested:true}` after authorized durable control admission, including a terminal race. This receipt contains no lifecycle status, result, usage, child state or retained error. GET/events require their independent current consumed-source proofs. The family signal immediately fences late claims, callbacks and child admission; bounded descendant bookkeeping follows separately. Cancellation preserves already committed business receipts and does not itself revoke a result completed before that signal. An interrupted pending or blocked observation still withholds its metadata and content.

Service-origin evaluations require a separate operator profile with `serviceAuthority`, `suiteServiceRevision`, `agentServiceRevision`, and `evaluatorServiceRevision`. All three exact registered purposes must belong to the same current service actor and application; the suite uses `evaluation-control`, and its pinned Agent and deterministic evaluator use `standard`. Registration is metadata only. The accepted suite captures the profile identity and its database generation. Disabling and reenabling the profile changes that generation and cannot revive accepted work.

Only an actual live case lease may admit either child purpose. The child receives its own approved service binding, the real case as its cancellation/deadline parent, and the intersection of the accepted case capabilities with current child capabilities. Admission checks the pinned suite Source proof, fixture read authority, inherited classifications, target identity and immutable profile. Linking the child to its case commits with the child's actual domain metadata. Public JSON cannot supply this witness or choose a service actor. The general service same-purpose guard remains unchanged. This composition and its new model-receipt/input-authority regressions are staged for fresh PostgreSQL/OCI proof; the earlier seven-test evidence does not qualify them.
